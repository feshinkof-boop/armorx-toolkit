# ATT-level evidence

## tshark attempt (honest record)

`tshark -r raw/btmon.btsnoop -Y btatt` returned **no frames** for this capture (capinfos: 231+
packets, encapsulation "Bluetooth Linux Monitor"). TShark 4.6.4 did not decode the btatt layer
here, so it is **not** the ATT evidence source. The mature tool `btmon -r <capture>` (the same tool
that recorded it) decodes ATT operations, handles and values, and was used instead.

Handles: FFE1 control write `0x0075`, FFE2 notify `0x0077`, FFE2 CCCD `0x0078`.
CCCD writes present in the capture: `0100` / `0000` / `0100` sequences - i.e. variant B's renewal

capture alone; B's attribution rests on its harness timeline
(`B-cccd-renewal/timeline-B-cccd-renewal.csv`: cccd_renew_start 35.478 s, unsubscribe_done
35.480 s, resubscribe_done 36.500 s).

## Coverage limitation (stated, not hidden)

The btsnoop contains **three** of the five run windows (A, C, C0 re-run). The first C0 window and
variant B's window are absent from the capture although btmon was running. Only A, C and C0
therefore have independent ATT confirmation; C0's semantics are proven by the re-run window.
No conclusion here depends on the missing windows.
