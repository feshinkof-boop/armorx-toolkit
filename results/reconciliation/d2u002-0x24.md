# D2-U-002 — the `0x24` comparison in the 2.24 analysisData parser

**Question.** In the 2.24 Dart AOT image, `_RainbowTestState::analysisData` (entry `0x91d130`) contains a gate
that compares a value to the immediate `0x24`. Does `0x24` mean a 36-byte frame length, the integer 18 in
Smi/tagged form, a container length, an array element index, a byte offset, an enum value, or something else?

**Answer (PROVEN STATIC).** `0x24` is the **Dart Smi (tagged) encoding of the integer 18** (`0x12 << 1`).
It is compared against **`data[1]`** — the frame's byte at index 1 — i.e. the frame's length/type field, whose
value is `0x12` (= 18) for a full 18-byte report frame. It is **not** 36, not a 36-byte frame length, not an
index, not an offset, not an enum value.

## 2. `w0` is a tagged Smi — proof

`w0` is the return value of a `List<int>` accessor. List elements in these images are stored **tagged**. Direct
instruction-level proof from the same class, 2.24 `testModeSwitch` (`0x91e380`, the D2 frame builder that
produces the live-confirmed `A5 05 D2 01 7D`):

```
0x0091e3c4: 512980d2 mov   x17, #0x14a          ; 330 = 2*165  -> element 0 = 0xA5
0x0091e3c8: 11f000b8 stur  w17, [x0, #0xf]
0x0091e3cc: 510180d2 mov   x17, #0xa            ;  10 = 2*5    -> element 1 = 0x05
0x0091e3d0: 113001b8 stur  w17, [x0, #0x13]
0x0091e3d4: 913480d2 mov   x17, #0x1a4          ; 420 = 2*210  -> element 2 = 0xD2
0x0091e3d8: 117001b8 stur  w17, [x0, #0x17]
0x0091e3dc: 510080d2 mov   x17, #2             ;   2 = 2*1    -> element 3 = 0x01
0x0091e3e0: 11b001b8 stur  w17, [x0, #0x1b]
0x0091e3e4: 511f80d2 mov   x17, #0xfa           ; 250 = 2*125  -> element 4 = 0x7D
0x0091e3e8: 11f001b8 stur  w17, [x0, #0x1f]
0x0091e400: 400180d2 mov   x0, #0xa             ; GrowableList length = 5, stored tagged (10)
0x0091e404: 20b000b8 stur  w0, [x1, #0xb]
```

Every byte of the frame is emitted as `2 x value`: 0xA5→0x14A, 0x05→0x0A, 0xD2→0x1A4, 0x01→0x02, 0x7D→0xFA,
and the list length 5 is stored as 10. **List elements and int fields in this image are tagged Smis.**

Therefore the value returned by the accessor (`w0`) is a tagged Smi, and the constant it is compared against
must also be tagged (the compiler emitted a direct tagged-vs-tagged compare, with no `sbfx` untag step before
it). Hence:

```
tagged(w0) == 0x24  <=>  untagged(w0) == 0x24 >> 1 == 0x12 == 18
```

## 3. Cross-version proof that the source constant is 18

The older builds compile *the identical gate* with an explicit untag and compare to **18**:

| build | gate-arg immediate | untag | compare instruction |

| 2.22.0901 | `0x8e2438: mov x16, #2` | `0x8e2450: 017c4193 sbfx x1, x0, #1, #0x1f` | `0x8e245c: 3f4800f1 cmp x1, #0x12`  (= **18**) |
| 2.23      | `0x8b06d0: mov x16, #2` | `0x8b06e8: 017c4193 sbfx x1, x0, #1, #0x1f` | `0x8b06f4: 3f4800f1 cmp x1, #0x12`  (= **18**) |
| 2.24      | `0x91d154: mov x16, #2` | *(none — tagged compare)* | `0x91d168: 1f900071 cmp w0, #0x24` (= **0x12 tagged**) |
| 4.0.8     | `0xacfa98: mov x16, #4` | *(none — tagged compare)* | `0xacfaac: 1f100071 cmp w0, #4`    (= **2 tagged**) |

Identical source, two encodings: 2.22/2.23 untag then compare to `0x12`; 2.24 compares the tagged Smi to
`0x24 = 0x12 << 1`. Same constant, same gate.

An **independent** check on the very same function confirms the tagged-vs-untagged pattern: the sibling
"length/print" gate inside the notify closure is

```
2.23  0x8b06ac: 3fe402f1 cmp x1, #0xb9     ; untagged 185
2.24  0x91d0ec: 1fc80571 cmp w0, #0x172    ; 0x172 = 2*185 = tagged 185
```

`0x172 / 0xb9 = 370/185 = 2` exactly, and `0x24 / 0x12 = 2` exactly. Two independent constants in the same
function, both doubled in 2.24 → 2.24 encodes comparison constants in tagged (2×) form.

## 4. The Smi arithmetic, step by step

1. Dart Smi encoding: `Smi(n) = (n << 1) | 0`. The low bit is the tag and is 0 for small integers.
2. `0x24 = 0b0010_0100`. Low bit = 0 → it is a **valid Smi** (not a pointer, not a Mint).
3. Untag: `n = 0x24 >> 1 = 0b0001_0010 = 0x12 = 18`.
4. Sanity: the tagged form of the integer **36** would be `0x24 << 1 = 0x48`, not `0x24`. So the literal value
   **36 is arithmetically excluded** — a Dart integer 36 can never be emitted as the immediate `0x24`.
5. Sanity: 18 fits in a Smi (18 < 2^30), consistent with a literal list/frame check.

## 5. Which byte is compared, and the branch taken

The accessor is called with **one** argument (the call pushes two stack slots — arg + receiver — and pops
`#0x10`; by contrast the closure's no-argument property getter pushes a single slot and pops `#8`). So the
accessor is an **indexed element read** (`operator[]`/`elementAt`), *not* the no-argument `.length` property.
The argument immediate is `mov x16, #2`; as a Dart argument it is a tagged Smi → index **1**.

Cross-check with 4.0.8, whose gate is live-pinned: 4.0.8 uses argument `#4` (tagged → index **2**) and constant
`#4` (tagged → **2**), i.e. `frame[2] == 2`, which matches the live frame `A5 12 02 ...` where byte[2] = 0x02.
The argument encoding is tagged in 4.0.8, therefore it is tagged in 2.24 → index **1**.

For 2.24 the gate is therefore:

```
if (data[1] != 18) return;        // byte 1 of the frame
```

- `data[1]` is the frame's **second byte**, the length field: the D2 frames are `A5 05 D2 …` (byte[1] = 0x05 = 5
  = total length), and a full report frame `A5 12 02 …` is 18 bytes with byte[1] = `0x12` = **18**.
- **Branch on equality:** equal → fall through to `0x91d170`, which does `data.sublist(3, 14)` →
  `Uint8List.fromList` → `asByteData` → length > 3 check (`0x91d1dc: cmp x2,#3`) → combine bytes [3][4][5][6]
  with masks `0xFF000000/0x00FF0000/0x0000FF00/0x000000FF` into the 32-bit big-endian key mask.
- **Branch on inequality:** `b.ne #0x91e23c` → `0x91e23c: mov x0,NULL; mov x15,x29; ldp x29,x30,[x15],#0x10; ret`
  — an immediate return, no parsing.

## 6. Alternatives tested and their status

| candidate meaning | status | why |
|---|---|---|
| integer **18** in Smi/tagged form | **CONFIRMED** | `w0` is a tagged Smi; `0x24>>1 = 0x12 = 18`; 2.22/2.23 untag and compare to `0x12` = 18. |
| a **36-byte frame length** / the raw integer 36 | REFUTED | 36 as a Dart integer is emitted as `0x48`, never `0x24`; and the compared byte is `0x12`=18, so `==36` would make the gate never pass. |
| a **container length** (`.length`) | REFUTED (as the operation) | the compared operand is an *element* (the accessor takes an argument; the no-arg `.length`-style property getter in the same class is a distinct call). Numerically the compared byte *is* the frame's length field, so 18 coincides with the frame size. |
| an **array element index** | REFUTED for `0x24` | the index is the separate immediate `mov x16,#2` = Smi 1 (= index 1); `0x24` is the compared value. |
| a **byte offset** | REFUTED | no address/offset computation involves `0x24`; it is a comparison operand. |
| an **enum value** | REFUTED | `data` is a plain `List<int>`; the operand is a tagged SmallInteger, not an enum/list index. |
| a tagged integer of another kind (Mint/heap int) | REFUTED | the tag bit is 0 and the value fits a Smi; no `AllocateMint…Stub` path is taken for this operand. |

## 7. Residual / negative observations (do not change the verdict)

- The dispatch-table target of `GDT[cid_x0 - 0x30c]` is not named in the dump (untyped slot). It is provably a
  one-int-argument accessor on `List<int>` returning a tagged Smi, which identifies it as `operator[]`
  (or `elementAt`) — i.e. an element read, not a property.
- Secondary observation, unexplained and out of scope: the immediately following `sublist` call pushes its range
  arguments as raw immediates `mov x0,#3` / `mov x16,#0xe` (0x91d174 / 0x91d184) rather than their tagged forms
  (`#6` / `#0x1c`). The reason is not established from the listing; it does not affect the gate, whose two
  operands are pinned by (a) elements being tagged Smis, (b) the 4.0.8 live-pinned gate, and (c) the 2.22/2.23
  explicit untag to 18.
