# ARMOR-X Xbox GIP input map (live, 2026-09-28)

One continuous capture, seven one-action popups, no capture restart. 48-byte type-`0x20` reports on the
interrupt IN endpoint, ~4 ms apart. Differential method: per-offset min/max/distinctness in each control
window against the idle window; monotonic counters rejected before any field was assigned; digital
controls required **two** repeat cycles.

| control | offsets | representation | rest | active | class |
|---|---|---|---|---|---|
| A | byte 4 | bit `0x10` | 1 | 17 | CONTROL-CORRELATED |
| M1 | byte 4 | bit `0x20` | 1 | 33 | CONTROL-CORRELATED |
| M2 | byte 5 | bit `0x40` | 0 | 64 | CONTROL-CORRELATED |
| LT | bytes 6-7 | 16-bit LE | 0 | ~1020 | CONTROL-CORRELATED |
| RT | bytes 8-9 | 16-bit LE | 0 | ~1020 | CONTROL-CORRELATED |
| LX | bytes 10-13 | two 16-bit LE | stable | full sweep | CONTROL-CORRELATED |
| RX | bytes 14-17 | two 16-bit LE | stable | full sweep | CONTROL-CORRELATED |
| sequence | byte 2 | 8-bit counter | varies 1..255 | - | SEQUENCE |
| counters | bytes 40-47 | two 32-bit | monotonic | - | TIMESTAMP |
| header/body | 0,1,3 and 18-39 | constant | - | - | CONSTANT |

**RT has no digital bit of its own in this report.** The RT window moved only bytes 8-9 (plus counters),
so the Xbox-side RT is purely analog here. Anything digital about RT on the ARMOR-X side is therefore
generated by the ARMOR-X, not copied from the controller report - which is directly relevant to the open
RT-only D2 question.

M1 and M2 do appear as device-side bits (byte 4 `0x20`, byte 5 `0x40`), so rear buttons are not
invisible to the host, contradicting the "never appears externally" hypothesis for at least those two.

Unproven: axis role separation (X vs Y) inside each stick pair, exact LT/RT scale semantics, M3/M4, and
whether bytes 40-47 are real timestamps.
