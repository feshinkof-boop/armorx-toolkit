# v0.5.0 Linux desktop GUI

Status: **development** on `dev/v0.5.0-linux-gui`.

Issue: #4 — desktop GUI for configuration and macro editing.

## Milestone 1

The first GUI commit establishes a PySide6/Qt desktop shell without duplicating
the protocol implementation.

Install from a development checkout:

```bash
python -m pip install -e ".[gui,dev]"
armorx-gui
```

Implemented in this milestone:

- BLE scan using `armorx.live.scan_ble`;
- select a discovered address and read the live config through the proven D6
  backend;
- open an existing JSON or 144-byte binary config offline;
- display identity, length and CRC state;
- edit M1-M4 mappings using the canonical recovered key IDs;
- edit a first set of proven byte fields for triggers, sticks, sensor mode and
  turbo speed;
- regenerate CRC automatically after every edit;
- exact byte-level change table using `armorx.diff`;
- reset to the immutable loaded baseline;
- export a validated JSON or binary target.

The GUI model lives in `armorx.gui_model`, independent from Qt, so config
editing and safety behavior can be tested headlessly.

## Write boundary

The **Apply & Verify** button is intentionally disabled in milestone 1.

v0.4.0 already has a proven, released `armorx live apply` /
`armorx live rollback` path. The desktop will reuse those same backend
functions, but the GUI write button is not enabled until its confirmation,
automatic-backup, progress/error and rollback UX have deterministic tests.
There will not be a second D6/D7/0E implementation.

## Next milestones

1. Wire GUI Apply & Verify to `armorx.live.apply_config` with a native Qt
   confirmation dialog and the same backup/diff/verification contract.
2. Add rollback/profile management and persisted local profiles.
3. Replace raw numeric curve controls with visual stick/deadzone/curve editors.
4. Add macro timeline editing on top of `armorx.macro`.
5. Package the Linux desktop app and add screenshots/documentation.

The package version remains 0.4.0 until the v0.5.0 GUI is hardware-validated.
