# v0.5.0 release readiness review

Status: **release candidate pending final branch CI**.

## Completed gates

- v0.4 guarded Linux BLE backend already released and retained unchanged as the
  single device write implementation.
- PySide6 GUI scan/read/edit/apply/rollback/profile path implemented.
- Supervised real GUI hardware validation: PASS.
- Physical M1 effect proven on passive USB wire.
- Target persistence and exact baseline restoration proven across power cycles.
- GUI-BUSY-001 fixed with offscreen Qt regression tests.
- Visual stick/trigger editors implemented with evidence-bounded raw-byte
  labeling and unknown-byte preservation.
- Offline V41 macro timeline implemented with 1..16 steps, chords and timing.
- Linux per-user launcher/desktop packaging implemented.
- Address-free screenshots generated for hardware-validated and synthetic tabs.
- Package version sources bumped to 0.5.0.

## Release blockers

Only final automation gates remain:

1. PR #10 CI green on Python 3.10–3.13.
2. Wheel/sdist/Linux desktop bundle build succeeds.
3. Clean wheel install reports `armorx 0.5.0` and launcher install/uninstall
   smoke passes.
4. SHA-256 manifest verifies all Linux package artifacts.
5. PR #10 merges to main and final main CI passes before tagging.

## Deliberately non-blocking

- Exact firmware response-curve transfer math remains unknown. The GUI labels
  its visualization as raw 0..255 byte space rather than presenting a false
  calibrated model.
- Device macro installation/D8 payload semantics remain a separate research
  gate. v0.5.0 edits/validates portable macro JSON offline only.
- Share/Screenshot key ID remains unresolved.
- Other firmware versions remain not independently hardware-validated.

No additional controller configuration write is required for the v0.5.0
release candidate.
